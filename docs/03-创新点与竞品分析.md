# 创新点与竞品分析


## 第五章  创新点与竞品分析

本章回答两个问题：**我们做了什么别人没做的**（创新点），以及**市场上已经有什么，我们如何立足**（竞品分析）。创新点按"通行做法 → 它的局限 → 我们做了什么不同 → 带来什么可验证的结果"四段展开，**每一条的结果都必须是已经能演示或测试的，不能是计划**。


### 5.1 四条创新点


#### 创新点一：以人体位置为索引组织长期观察记录

**通行做法**：健康记录类应用普遍按时间组织，照片按时间倒序排列。

**局限**：皮肤问题恰恰是"同一处反复发作"，按时间排列会让同一个部位的记录散落在几十条无关记录之间；而且皮肤问题常常同时出现在多个部位，时间线根本无法回答"我右胳膊那处现在怎么样了"。

**我们的不同**：把三维人体作为空间索引，每条记录挂在身体的具体位置上，同一部位的历史自动串成一条时间线；书签会随视角旋转，朝向背面或被遮挡时自动隐藏，让"人体"成为一个真正可用的索引而不是装饰。

**可验证的结果**：现场演示——在人体背面新建一个位置，刷新后书签仍在（有浏览器测试覆盖）；转动人体时背面的书签正确隐藏。


#### 创新点二：把"可比性"做成产品能力

**通行做法**：多数应用只负责存照片，是否可比、怎么比，留给用户自己解决。

**局限**：角度、距离、光线不一致的照片放在一起，很容易把"拍得近"误读成"变严重了"。没有可比性的对照，比没有对照更危险——它会给出错误的结论。

**我们的不同**：两步解决。第一步是复查时的**构图参考**：把该部位上一次的照片调成半透明叠影压在实时画面上，帮助用户拍出角度一致的照片，且叠影只用于取景、不会被混入新照片（有像素级测试验证）。第二步是**诚实的不确定处理**：两条记录角度差异大时，不给出变化百分比、不给出改善结论，只呈现影像与症状本身。

**可验证的结果**：现场演示滑动对照与叠影拍摄；像素级测试证明叠影不会污染新照片。


#### 创新点三：把隐私做成架构，而不是承诺

**通行做法**：应用在上传用户照片的同时，在隐私政策里承诺"我们会保护你的数据"。

**局限**：承诺无法被用户验证，而皮肤照片属于敏感个人信息的范畴，用户只能选择相信或不用。

**我们的不同**：不设服务端。整个应用在浏览器本地运行，运行期没有任何外部网络通信（有测试断言）；照片默认不写入档案，且这条规则写在数据层；记录中存放分析结论的字段在结构上容纳不了未经模型验证的结论。

**可验证的结果**：**当场打开开发者工具的网络面板走完整流程，可以看到零外部请求**。这是本项目最有力的演示，也是唯一一个"不需要评委相信我们"的创新点。


#### 创新点四：面向不确定的诚实输出

**通行做法**：演示型原型常把识别结果写死，让界面看起来功能完整；或对低质量输入也强行给出结论。

**局限**：前者在答辩追问时会当场穿帮；后者在真实使用中会给出错误判断——在健康场景里，一个错误的结论比没有结论更糟。

**我们的不同**：在没有接入识别模型时，真实照片走到的界面明确显示"本次尚未进行 AI 识别"，**不用任何写死的假结果填充产品**；唯一的示例内容需要用户主动点击"使用内置示例"才会出现，且带有"示例结果 · 非诊断"标记，与真实输入完全隔离。这条设计原则已经写进下一阶段的规划：图像质量评估与拒识条件被列为比识别精度更重要的待明确问题。

**可验证的结果**：演示导入一张真实照片，界面上不会出现任何病名或概率（有测试断言真实输入不出现示例疾病文字）。


### 5.2 四类竞品全景

与本项目相关的方案可以归为四类。它们的共同点是都在帮人处理皮肤问题，差异在于**"变化"这件事被处理到了什么程度**。

| 竞品类型 | 代表形态 | 优势 | 局限（本项目的切入点） |
|---|---|---|---|
| 通用记录工具 | 手机相册、备忘录、云盘 | 零门槛、人人都有、免费；不改变用户习惯 | 没有部位标签、没有症状结构、没有可比性设计；几周后连"是哪一侧"都认不出，**恰恰无法回答"变化"这个问题** |
| 皮肤自查类应用 | 手机拍照 → 上传云端 → 返回疑似病种与建议 | 识别结果是用户最想要的东西；体验轻 | 照片必须上传，隐私顾虑让一部分用户在第一步就放弃；多为一次性自查，**不做长期连续记录**；对低质量输入常强行给结论 |
| 健康管理类应用 | 用药提醒、症状日记、健康数据看板 | 有结构化记录与提醒能力，习惯养成机制成熟 | 记录是"按时间"而非"按部位"；缺少三维部位索引与照片的对照能力；体量偏重 |
| 专业皮肤影像设备 | 皮肤镜数字系统、医院皮肤影像与远程会诊平台 | 影像质量高，与临床流程贴合 | 面向医院而非家庭；价格高、门槛高；**目标是临床判读，不解决家庭日常记录问题** |


### 5.3 竞品矩阵

下表把四类竞品与本项目在关键维度上对照。**注意最后三列：部位索引、可比性设计、可验证的隐私，是本项目相对所有同类方案最明确的差异点。**

| 维度 | 通用记录工具 | 皮肤自查应用 | 健康管理应用 | 本项目（肤镜） |
|---|---|---|---|---|
| 按身体部位组织 | 否 | 否 | 否 | **是（三维人体索引）** |
| 照片可比性设计 | 否 | 否 | 弱 | **是（构图参考 + 对照）** |
| 连续观察时间线 | 否（仅按时间堆叠） | 弱 | 是（按时间） | **是（按部位 + 时间）** |
| 照片是否上传 | 视云盘设置 | 是 | 常见 | **否（无服务端）** |
| 可验证的隐私 | 否 | 否 | 否 | **是（可当场检查网络请求）** |
| 免注册免登录 | 通常需要 | 通常需要 | 需要 | **是** |
| 离线可用 | 部分 | 否 | 否 | **是** |
| 识别能力 | 无 | 有 | 弱或无 | **【下一阶段】** |
| 成本 | 免费或订阅 | 免费 + 增值 | 订阅 | **本地应用，成本低** |

这张表必须诚实呈现一列事实：**在"识别能力"这一行，竞品里的皮肤自查类应用是"有"，我们是"下一阶段"。**我们不能靠回避这一行来赢。本项目的立足点是另一个问题：**识别给出的是"这一次像什么"，而我们解决的是"这一处这段时间怎么了"。**前者是一次性的判断，后者是长期的记录——而后者恰恰是判断"该不该去医院"所需要的。**两者的关系不是替代，而是互补；识别能力是我们明确规划的下一阶段，而不是我们回避的问题。**


### 5.4 差异化定位与壁垒

一句话概括本项目的差异化：**别人帮你判断"这一次像什么"，我们帮你记住"这一处这些日子怎么变的"，而且这份记录只在你自己的设备上。**

| 壁垒层级 | 内容 | 为什么难以被快速复制 |
|---|---|---|
| 第一层：交互设计壁垒 | 三维人体部位索引、书签遮挡处理、二维降级、复查构图参考 | 三维点选与遮挡判定的细节很多（射线拾取、法线朝向、投影隐藏、节流），是把三维真正做成"可用索引"的工程积累，不是接一个三维库就能得到 |
| 第二层：数据与隐私架构壁垒 | 本地优先的档案模型、写入前校验、事务语义、照片默认不留存、结构上容纳不了未验证结论 | 对以云端为中心的团队来说，改成"完全本地"意味着重做整个数据层；而一旦"照片不上传"成为用户的硬性要求，云端方案就出局 |
| 第三层：诚实性的信任壁垒 | 明确的边界标注、不用假结果填充、可当场验证的隐私 | 这是一条需要长期一致行为才能建立的信任，也是一旦破坏就很难修复的资产 |
| 第四层：下一步的模型与临床壁垒 | 识别模型与临床判读的一致性验证 | **尚未建立**。这需要真实数据与合作医疗机构，是明确规划的下一阶段 |

需要诚实地指出：**本项目目前站稳的是第一、二层壁垒，第三层正在通过产品行为积累，第四层尚未开始建设。**如果被问"你们凭什么挡得住大厂"，正确的回答不是"我们更快"，而是"我们把一件大厂不屑于做的事做扎实了——一本完全离线的、按身体部位组织的家庭手账；并且我们宁可让识别功能显示"尚未接入"，也不填一段假结果"。
