# 肤镜 · 家庭皮肤手账：UI 与功能设计方案

日期：2026-10-09  
状态：需求访谈后的概念方案；尚未编写产品代码或验证识别能力。  
命名：“肤镜”沿用项目材料中的暂定品牌，“家庭皮肤手账”为产品体验描述，未另行确认品牌名称。

## 1. 已确认的需求

本方案以本轮对话为准。原项目材料提供技术背景；其中面向医生的产品定位，需要随本轮需求调整。

| 项目 | 已确认的选择 |
|---|---|
| 第一目标 | 实际使用体验优先 |
| 主要使用者 | 普通用户本人及家属 |
| 主要终端 | 电脑网页，鼠标与键盘操作 |
| 使用场所 | 暂不限定，先完成个人电脑上的产品体验 |
| 关注范围 | 湿疹、皮炎、痤疮等常见皮肤问题的初筛；实际支持病种须由后续模型验证确定 |
| 功能范围 | 个人档案、检查记录、历史回顾、复查对比、随访安排 |
| 输入方式 | 导入已有照片、摄像头现场拍摄，两种均支持 |
| 症状输入 | 轻量点选，可选文字补充 |
| 档案组织 | 本人和家人分别拥有独立记录 |
| 访问方式 | 免注册、免登录，打开后选择家庭成员 |
| 照片留存 | 由用户主动选择是否保存到本地档案 |

| 主交互 | 可旋转、缩放、选择部位的 3D 身体地图 |
| 人体风格 | 暖白或浅灰的哑光雕塑 |
| 重点配套 | 前后照片对照、复查时的拍摄参考，两项都纳入设计 |
| 检查结果 | 疑似疾病方向、易懂的观察依据、不确定性、复查或就医指引 |

## 2. 产品概念：把一处皮肤的变化，写成一本可以回看的手账

用户打开网页，首先看到当前家庭成员的暖白人体模型。身体上的小书签代表用户记录过的位置；点开一个书签，旁边出现这一处皮肤的观察时间线。

产品围绕三个动作建立记忆：

- 找到这一处：在身体地图上定位问题，进入对应档案。
- 看见它的变化：回顾照片与症状，按时间对照。
- 继续记录：沿用部位与上次构图，完成下一次检查。

核心组织关系为“家庭成员 → 观察部位或具体问题 → 多次检查”。同一位置的长期问题保持连续记录；旧问题结束后新出现的问题可以另建记录，避免把不同问题拼接为同一段病程。

3D 人体承担导航和位置记录作用。标记位置来自用户选择，模型外观不代表用户身体的精确重建；未标记的区域表示尚无记录。

## 3. 首页：像打开一本带有立体索引的观察册

### 桌面布局

| 区域 | 画面与内容 | 主要交互 |
|---|---|---|
| 顶部细导航 | 品牌、当前成员、皮肤手账、复查计划、设置 | 成员切换始终可见；无需经过登录页 |
| 主视区左侧，约六成宽度 | 哑光人体、轻柔落地阴影、部位书签，周围保留留白 | 拖动旋转、滚轮缩放、正面/背面按钮、复位 |
| 主视区右侧，约四成宽度 | 当前部位的标题、最近记录、照片或文字摘要、时间线 | 阅读、展开记录、比较、再次检查 |
| 右侧顶部主操作 | “记录新变化”；选中旧书签时为“为这一处复查” | 清楚区分新问题与已有问题的后续记录 |
| 页内轻提示 | 当前成员近期的复查安排 | 跳转到具体部位与日期，不用泛化分数概括健康 |

未选择书签时，右侧呈现当前成员最近的观察与待复查事项。选中后，右侧内容收敛到同一处皮肤，避免在阅读中混入其他家人的记录。

人体是视觉中心，右侧手账是阅读中心。常用操作使用文字按钮，图标提供辅助；日期、照片说明与部位标题采用有节奏的排版，保留个人记录的亲切感。

### 首次打开

首页直接提供“建立第一位成员”。只要求一个称呼，年龄段等信息按实际必要性补充。创建后，人体旁出现一句引导：“在身体上选一处，开始第一条记录。”

可通过人体点选，也可使用“按部位选择”的文字入口。完成第一条记录后，该位置出现第一枚书签，首页自然转为日常使用状态。

## 4. 页面与功能结构

| 页面或面板 | 要解决的事 | 关键内容 |
|---|---|---|
| 身体手账首页 | 找到人、找到部位、继续记录 | 成员切换、3D 地图、部位书签、观察时间线 |
| 家庭成员面板 | 为本人及家人管理独立资料 | 称呼、可选年龄段、编辑与删除；每人的记录数量与近期安排 |
| 新检查流程 | 提供可靠的照片和必要症状信息 | 部位确认、导入/拍摄、质量反馈、症状卡 |
| 检查结果页 | 看懂本次提示和下一步 | 疑似方向、观察依据、信息不足项、行动指引、保存选项 |
| 部位手账详情 | 回顾同一问题的连续过程 | 日期、照片、症状、结果、个人备注、复查计划 |
| 变化对照视图 | 比较两次记录 | 时间选择、左右并排、可选滑动对照、症状变化 |
| 复查拍摄视图 | 尽量重复相近拍摄条件 | 上次构图参考、透明度调节、当前画面质量提示 |
| 复查计划 | 让后续记录有连续性 | 按成员与日期查看、完成、改期、取消 |
| 数据与设备设置 | 管理本地资料与检测设备 | 数据导出/删除、保存说明、设备连接与检测服务状态 |

“前后对照”和“复查拍摄”从具体部位的手账进入，始终保留当前成员与部位信息。

## 5. 一次检查的完整体验

### ① 选择成员与部位

用户选择家庭成员，在人体上确定大部位，再放大到具体位置。页面用文字确认，例如“左前臂 · 外侧”。左右以被记录者自身为准。

较小部位可通过列表快速定位。正式保存前，用户能够修正位置，避免把旋转后的屏幕左右误认为身体左右。

### ② 导入或拍摄

提供“选择已有照片”和“打开摄像头”两个同等清楚的入口。图片进入后先确认内容与质量，再进行分析。

质量反馈直接说明可执行的改进，例如“画面有些模糊，请保持稳定后重拍”。具体提示依赖对应质量检测能力；尚未实现的判断不能伪装成自动检测结果。

用户可以重拍、重新选择或取消。摄像头权限被拒绝时仍能使用照片导入。

### ③ 点选症状

以少量选项卡采集本次情况，初步建议包括：

- 感受：无明显不适、痒、痛、灼热、不确定。
- 持续时间：刚出现、几天、几周、更久、记不清。
- 最近变化：基本不变、范围扩大、有所缓解、反复出现、不确定。

补充文字为可选项。复查时展示上次的选择，要求用户确认本次情况，避免直接复制成新的事实。

症状记录用于完整呈现用户描述。只有经过验证的模型或规则才能将其参与识别与行动建议；仅采集了症状，不等于系统已经具备多模态推理能力。

### ④ 阅读本次观察

结果按“本次观察 → 疑似方向与依据 → 下一步”组织。用户可展开更多说明，不必先读完一整页医学术语。

结果页始终显示成员、部位、日期与当前照片，降低关联错人的可能。图片不足以支持判断时，页面提供补充信息或就医方向，并允许保存这次未完成判断的观察记录。

### ⑤ 保存与安排复查

点击“保存本次记录”后，写入所确认的结构化内容。照片单独提供“将本次照片保存在本地手账”选项，初始不勾选。

保存照片后，可供后续对照与构图参考；未保存照片的记录仍可回顾症状、日期和结果。界面明确显示“本次未保存照片”，不生成看似真实的替代缩略图。

用户可以添加复查日期、备注，或暂不安排。没有经过验证的依据时，不自动给出具有医疗含义的固定复查周期。

## 6. 三项标志性交互

### A. 3D 身体地图：用身体位置组织手账

人体采用暖白哑光材质、柔和轮廓光和轻微阴影。默认视角稳定，点击书签后以短暂转动将部位带到方便观察的位置。

书签表现为小圆点与短标签，标签可以显示部位名称、最近记录日期。橙色用于选中与交互强调，记录状态配合文字和形状表达，不把所有橙色书签解释为危险。

同一片区域书签较多时先聚合，放大后展开。身体背面的记录通过正面/背面入口找到；选中列表中的记录也能使模型转向对应位置。

手、足、面部等小范围支持局部放大与文字确认。无需用户在全身小模型上进行高精度点击。

每枚书签至少关联成员、部位、左右侧、位置记录和观察条目。用户可以修改标记位置，保留历史检查；同一区域出现新的独立问题时可以另建条目。

同时保留二维正反面与文字列表入口，使低性能电脑、图形加载失败以及键盘操作仍能完成核心任务。3D 的可用性需要与人体资产、加载性能一起验证。

### B. 变化对照窗：同一处，两次观察

默认从同一部位手账中选择两次记录。清楚标注日期，并把症状变化与照片放在同一视图中。

拍摄条件接近时提供滑动对照；角度或构图差异较大时优先使用左右并排。用户可同步缩放查看细节，原始图片保持不变。

对照页保留三类信息：

- 影像：用户能够自己观察到的差异。
- 症状：用户两次填写的感受与变化。
- 分析：经过验证的算法实际支持的变化判断。

不同光照与拍摄距离会影响外观，因此颜色变浅、像素区域变小不能直接等同于病情改善。没有尺度标定时不显示精确毫米数或面积变化百分比；不能仅依据未经验证的前后照片自动宣布痊愈。

缺少历史照片时仍可比较文字与症状，同时说明影像对照所需条件。

### C. 复查拍摄向导：让下一张照片更容易比较

从“为这一处复查”进入，自动带入成员与部位。若存在用户已保存的历史照片，可将其作为可调透明度的构图参考。

用户依次对照位置、距离和角度，并查看当前画面是否清晰。参考图可随时隐藏，避免遮挡实时画面。

历史图叠加只用于取景辅助；正式保存与分析使用本次独立拍摄的原始画面。引导完成后展示新照片，让用户确认是否可用。

没有历史照片时提供一般拍摄引导，不假设系统拥有未被保存的画面。对难以自行拍摄的部位，支持由家人协助操作。

## 7. 检查结果怎样让普通用户看懂

| 层次 | 用户看到的内容 | 设计要求 |
|---|---|---|
| 本次观察 | 可支持的皮肤表现与用户症状摘要 | 区分模型观察、用户自述与历史记录 |
| 疑似方向 | 少量可能的常见皮肤问题及通俗解释 | 始终使用疑似或可能表述；支持范围以验证结果为准 |
| 判断依据 | 与本次输入有关的可复核线索 | 只有存在真实依据时才联动图片标注 |
| 仍需确认 | 图片质量、缺少的信息、超出能力的情况 | 让用户知道可以补充什么 |
| 下一步 | 补充信息、继续记录、复查或就医方向 | 建议逻辑需验证，避免越过产品能力边界 |

低置信度、超出适用范围、图片不合格和设备不可用是不同状态，应提供不同的说明与操作入口。

面向湿疹、皮炎、痤疮等场景，解释应围绕适用的皮疹表现、分布、病程与症状组织。原材料中用于色素性皮损的 ABCD 指标，不作为所有常见皮肤问题的统一评价尺度。

首版不以精确概率或综合“皮肤健康分”作为视觉中心。未完成校准与评测时不编造概率、准确率和识别速度；可解释标注也不意味着已经证明疾病原因。

导出的内容称为“皮肤观察摘要”，用于回顾或就医沟通，包含日期、部位、用户描述、系统提示与适用限制。药物、处方和自动治疗方案不属于本轮确定的功能。

## 8. 家庭、本地保存与免登录的具体含义

### 家庭成员

成员切换贯穿拍摄、查看和保存。切换前若存在尚未保存的记录，应先完成或放弃当前操作，避免将照片存入另一位家人的档案。

无需收集身份证号、联系电话等无关信息。称呼足以开始使用，其他字段只在必要时添加。

本轮选择了免登录，因此家庭成员是记录分组，不代表账号权限隔离。能使用当前设备的人可以进入家庭空间；界面可提供临时遮挡照片的功能，但不能把遮挡宣传为访问控制。

### 照片与结构化记录

- 照片默认仅用于本次操作，用户明确选择后才写入本地档案。
- 用户确认保存的日期、部位、症状、系统结果与备注，可以在没有照片时独立形成记录。
- 未保存照片在本次会话结束后不作为系统档案留存；实际清理机制需在实现时验证。
- 导入照片的原始文件由用户管理；取消保存或删除系统副本，不删除用户电脑中的源文件。
- 删除照片时允许保留文字记录；删除整条记录或整个成员前明确展示范围并确认。
- 导出由用户主动触发，展示包含哪些成员、记录和照片。系统不自动向云端传送原始影像。

### “本地”的部署边界

电脑网页与 RK3576 的连接方式尚未确定。本方案要求影像在用户的本地系统中处理，照片按用户选择本地保存；具体保存在电脑还是边缘设备，需要后续结合部署明确。

如果图像在电脑与 RK3576 之间传输，就不能继续用“影像绝不离开 RK3576 单台设备”的口径。现阶段适合使用“影像不上传云端，经用户选择可保存在本地”的设计目标。

浏览器或设备故障可能影响记录保管，方案预留用户主动导出与备份入口；存储方式、清理机制和恢复能力需在实现阶段验证。

## 9. 复查与日常使用

复查计划以“成员＋部位＋日期”组织。用户可以从具体手账添加计划，也可以在日历中查看全家的安排。

完成复查应产生一条新的观察记录，并与原计划关联。改期和取消保留清楚的操作反馈。

首版设计以网页内的待办提醒为基础。关闭网页后的通知依赖后续选择的本地服务或通知机制，不预先承诺短信、微信或持续后台推送。

进入已有记录时，用户可以选择继续观察、添加备注、发起复查或结束关注。结束关注属于用户的记录管理动作，不自动改写为医学上的痊愈。

## 10. 视觉与动效规则

| 项目 | 设计方向 |
|---|---|
| 页面底色 | 纸白，可从 #F6F2EB 开始探索 |
| 主文字 | 墨黑，可从 #262421 开始探索 |
| 强调色 | 暖橙，可从 #B85735 开始探索；用于书签、选中态与主操作 |
| 面板与分隔 | 接近纸面的浅色，细线分隔，边界明确 |
| 人体材质 | 暖白/浅灰哑光，保留轮廓和柔和体积感 |
| 排版 | 较大的部位标题、清晰的日期、舒适的正文；中文正文以约 16px 为起点 |
| 图片区域 | 保持原始影像色彩；专业对照区域使用中性背景，照片不套暖色滤镜 |
| 动效 | 部位聚焦、面板展开、书签反馈；短暂且由用户动作触发 |
| 静止状态 | 模型停止转动，让用户能稳定观察与阅读 |
| 无障碍 | 状态配文字与图形、明显焦点、可键盘操作、减少动态效果选项 |

颜色、字号与按钮尺寸是设计起点，需在后续视觉稿中校核对比度、清晰度及常见电脑屏幕上的可用性。

## 11. 功能推进顺序

以下是实现依赖顺序；三项标志性交互都属于整体设计范围。

| 顺序 | 工作内容 | 需要得到的结果 |
|---|---|---|
| 1 | 家庭成员、观察部位、记录归属、本地保存与删除规则 | 核心数据关系及保存边界清楚，成员与部位不会串档 |
| 2 | 身体地图、导入/拍摄、症状卡、记录时间线 | 形成完整的日常记录体验 |
| 3 | 质量检测、实际模型服务、结果页各类状态 | 分析结果有真实能力支撑，失败与信息不足可处理 |
| 4 | 照片对照、复查取景参考、复查计划 | 跑通连续记录与回顾的闭环 |
| 5 | 数据导出与备份、设备联调、保存与清理行为验证、性能验证 | 明确可部署范围，并验证实际运行效果 |

概念演示所用示例必须标明为示例。模型尚未接入时，用户真实上传的图片不能被返回一组模拟病名和概率并显示为已完成识别。

## 12. 与现有项目材料需要统一的地方

| 现有材料 | 本轮确定的设计方向 | 后续同步要求 |
|---|---|---|
| 基层医生端为主 | 普通用户与家庭使用 | 更新使用者、文案、解释深度和完整用户流程 |
| 影像分析后立即丢弃 | 用户主动选择本地留存照片 | 区分临时分析与明确保存；更新隐私口径 |
| 历史影像对比 | 仅对用户已保存的影像提供历史对照 | 缺少照片时只比较可用的症状和结果 |
| 影像不出单设备的表述 | 电脑网页与边缘设备的本地连接尚待确定 | 按真实数据流表述本地处理与不上云 |
| 色素性皮损的 ABCD 解释占较大篇幅 | 常见皮肤问题优先 | 重新确认任务、指标、数据和适用解释 |
| 皮肤镜公开数据集作为核心示例 | 普通相机拍摄的日常皮肤问题 | 验证数据域匹配，不能直接外推识别能力 |
| 医生作最终判读的流程 | 用户直接阅读结果与就医指引 | 明确不确定性、支持范围和就医引导的验证要求 |

本文件记录设计方向，不代表识别性能已经达成，也不替代后续临床、产品适用范围及相关分类的专业评估。

## 13. 后续验收情景

这些是未来设计与实现的验收目标，尚未执行。

1. 新用户无需注册即可建立成员，选定部位并完成第一条记录。
2. 同一位置能连续记录多次检查；同一区域的新问题可以单独建档。
3. 家庭成员切换后，地图、照片、历史和提醒始终属于当前成员。
4. 用户能通过人体模型或文字部位列表完成相同任务。
5. 导入照片与摄像头拍摄进入相同流程；摄像头不可用时有明确替代入口。
6. 模糊图片、超出支持范围、无法确定和设备不可用的状态不会被混为一类。
7. 不保存照片也能保留用户确认的结构化记录，之后明确显示照片不可回看。
8. 保存照片后，可从同一部位进入历史对照及复查拍摄参考。
9. 构图参考不会混入新的原始照片，也不会被当作新的分析输入。
10. 3D 加载失败时仍能选择部位、查看记录和发起检查。
11. 系统不在没有标定的情况下呈现精确尺寸变化，不把不同拍摄条件误写为已验证的改善。
12. 免登录、本地存储、照片留存与导出的实际行为和界面说明一致。

剩余实施细节包括人体资产来源、摄像头连接位置、网页与 RK3576 的通信方式、实际支持病种、存储位置和模型评测标准。它们需要在技术验证阶段落实，不影响当前已确认的产品与视觉主线。
