## 怎么用

1. **了解项目**：打开作品书。第一章是全书的浓缩版。
2. **讲清现状**：**先看 1.1 与 1.4**——本项目最重要的一件事，是把"已完成"与"下一阶段"讲清楚。
3. **写商业计划书**：附录 A 是章节对照表，逐行往下填即可。
4. **做答辩 PPT**：附录 B 的 18 页结构。**必须用真实产品截图，不要用示意图**——我们手上确实有可运行的软件。
5. **准备答辩问答**：附录 C 的 Q1–Q16。**Q3 与 Q4 必须背诵**，它们问的是"识别功能在哪"。
6. **推进项目**：附录 D 的素材清单，★ 项优先。
7. **提交前自查**：附录 E，逐项清零。

## 三条最重要的口径纪律

1. **识别功能的状态全文统一为"尚未接入、下一阶段"。**不得出现"已实现智能识别""识别准确率"这类表述。
2. **覆盖率 96.0% 必须写明口径**——只统计三个核心逻辑文件，不代表全部界面代码。
3. **不得为识别功能编造任何数字。**准确率、召回率、端侧帧率目前都不存在。正确的答法是承认现状、说明路线，把手上的原型讲透。

## 修改方式

内容全部位于 `tools/content.py`，用一套小型 DSL 描述
（`h1/h2/p/b/tbl/code` 等），排版逻辑位于 `tools/build_brief.py`。改完重跑：

```bash
python tools/build_brief.py
```

脚本会同时刷新 docx 与 docs/ 下的 Markdown 分卷，两者内容天然一致。
全文档字体统一为**宋体**（含西文与数字），由 `force_song_everywhere()`
与逐 run 的 `rFonts` 设置双重保证。

排版上有三条自动化规则，改内容后无需手工调版：

- **小表格整表同页**：估算行数 ≤ 21 的表格自动保持在同一页，避免被拆断后只剩一两行孤悬在下一页；需要强制或禁止可对 `tbl()` 传 `keep=True/False`。
- **标题与表格不孤行**：标题、表格表头行、附录 C 的问题段落均设为"与下段同页"，避免标题或问题落在页底而内容翻页。
- **不要手画带右边框的字符画方框图**：在非等宽的宋体下，中英文混排的字符画右边框无法稳定对齐，横线会明显短于内容宽度（本项目踩过这个坑）。需要方框时改用 Word 表格；纯流程示意改用无右边框的左向流程（`↓` 加缩进）。

改完内容后建议依次执行：

```bash
python tools/check_quotes.py tools/content.py   # 引号预检
python tools/check_content.py                   # 加粗标记与残留符号预检
python tools/build_brief.py                     # 生成 docx + md
python tools/verify_brief.py                    # 字体结构自检
python tools/export_pdf.py && python tools/render_png.py   # 导出并出图
```

说明：本文档每一章都从新的一页开始，因此每章**最后一页**留白偏多
（当前 43 页中有 2 页属此情况），这是该排版约定的正常结果
（正式申报材料普遍如此），并非缺陷。
若希望消除留白，把对应章节的 `pb()` 标记删去即可让正文连续排版。
